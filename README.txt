ПРОТОТИП ОБРАБОТКИ ОБРАЗОВАТЕЛЬНЫХ УЧРЕЖДЕНИЙ

Интерфейс в браузере: python -m ou_processor.web
На macOS можно открыть «Запустить UI.command». Инструкция: UI_README.txt.

Полный режим: DaData → резервный реестр аккредитации → объединение по ИНН.
Главный результат — одна строка на юридическое лицо: официальное название,
адрес, ФИО учеников, номера личных дел. ФИО и номер в соседних ячейках
соответствуют друг другу по порядку строк. Лист «Ученики и дела» даёт ту же
связь отдельной строкой для каждой пары.

Установка (Python 3.10+), из папки prototype:
  python3 -m venv .venv
  source .venv/bin/activate
  python -m pip install -r requirements.txt
На Windows: .venv\Scripts\activate

Сначала скачать резервный реестр (большой архив):
  python -m ou_processor.registry update
Подробнее — REGISTRY_README.txt. Реестр аккредитации отличается от реестра лицензий.

Полный поиск всех учреждений:
  python -m ou_processor.full_run "/путь/исходный.xlsx" --output run_all --cache dadata_cache.json --online --ask-token
Можно передать несколько файлов перед параметром --output.
Ключ вводится без отображения и не сохраняется. Альтернатива — переменная
DADATA_API_KEY и запуск без --ask-token. ФИО и номера дел не передаются в API.

--registry задаёт папку снимков реестра (по умолчанию ../registry_cache).
--cache содержит только ответы об организациях, без ключа и данных учеников.
Повторный запуск использует успешные ответы из этого файла. Для свежих
ответов DaData укажите новый файл кэша. Даты ответов сохранены в журнале.
Для повторного расчёта без сети уберите --online и --ask-token; незапрошенные
ранее варианты будут явно отмечены как пропущенные, код завершения 2.
Неудачные запросы не кэшируются. При 401/403/429 дальнейшие сетевые запросы
останавливаются, но локальный резервный поиск продолжается.
Папка --output должна быть новой/пустой. Исходные Excel не изменяются.

Как выполняется сопоставление

1. Читаются .xlsx с заголовками в первых 30 строках. Отбор: среднее общее,
   СПО/НПО; высшее исключается. Учитывается вид образования, а при его
   отсутствии — документ. Строки с противоречиями сохраняются на проверку.
   В аналитической книге читается только лист «100 записей», а не выводы аналитиков.
2. Нормализация раскрывает известные сокращения, убирает различия регистра,
   кавычек и пробелов. Исходные названия сохраняются.
3. Каждая предварительная группа проходит DaData. Если полного названия
   недостаточно, выполняются более короткие запросы с названием, номером
   и географией. Одинаковые запросы используют общий кэш.
4. Проверяются тип учреждения, номер, известные регион/город, ИНН и статус.
   Музыкальные, спортивные школы и школы искусств не подставляются вместо СОШ.
   Номер школы без города недостаточен. Для именных учреждений оценивается
   совпадение значимых слов. Полное название в кавычках уточняет неоднозначную
   выдачу. Обрезанные названия и возможные подразделения вузов требуют проверки.
   Словарь географии ограничен config.json; это не полный справочник ФИАС.
5. При отсутствии допустимого совпадения используется локальный реестр.
   Поиск ограничивается известным регионом. Исторические/недействующие записи
   и филиалы не считаются автоматическим подтверждением. Выдача с достигнутым
   ограничением не принимается за уникальное совпадение.
6. Несколько подходящих ИНН сохраняются для проверки. Автоматическое
   сопоставление — результат правил, а не независимая ручная проверка.
   Процент на листе кандидатов — доля совпавших слов, не вероятность точности.
7. Сопоставленные группы объединяются только по ИНН. Пара ФИО + номер дела
   удаляется как дубль внутри этого ИНН. Одноимённые ученики с разными делами
   остаются отдельно. Неполные пары не объединяются. Номер дела сам по себе
   не служит основанием объединять учреждения.
8. DaData даёт юридический адрес. Реестр — адрес организации в записи
   аккредитации; он помечен как требующий сверки. Это не обязательно адрес
   конкретного корпуса. Разные адреса одной организации не выбираются случайно.

Содержимое schools.xlsx

Учреждения — итог по ИНН; учреждения с учениками идут первыми.
Ученики и дела — сохранённые связи школы, ученика и номера дела.
Проверить — несопоставленные/неоднозначные случаи и первые три кандидата.
Сводка — количество входных строк, результаты сопоставления, источники и даты.
Исходные записи — все исходные записи, включая исключённые, с причинами и ID.
Запросы DaData — все запросы/ответы, даты, отметка кэша и ошибок.
Кандидаты — первые пять различных ИНН на группу; полный аудит в result.json.
Источники — входные файлы, количество строк и контрольные суммы.
Числа в книге рассчитываются Python; для обновления надо повторить запуск.

Основные модули
  input.py / pipeline.py — чтение, отбор, нормализация и предварительные группы
  resolution.py — полный поиск, правила идентификации, резервный поиск
  full_run.py — итог по ИНН, пары учеников и дел, Excel и CLI
  dadata.py — HTTP-клиент DaData
  registry.py — загрузка, индексация и обновление реестра
  export.py — оформление Excel

Проверки:
  python -m unittest discover -s tests -q
  python verify_full.py "/путь/к/итоговой_папке"
verify_full.py предназначен для пяти приложенных книг (140 строк, 10 учеников).

Старый демонстрационный режим остаётся доступен:
  python -m ou_processor "/путь/исходный.xlsx" --output sample --online --ask-token --dadata-limit 5
Результаты демонстрационных прогонов и исходные контрольные книги
в репозиторий не включены.

Документация DaData: https://dadata.ru/api/suggest/party/
