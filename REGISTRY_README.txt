РЕЗЕРВНЫЙ РЕЕСТР РОСОБРНАДЗОРА

Источник

Это реестр организаций, осуществляющих образовательную деятельность по
аккредитованным образовательным программам. Он отличается от сводного реестра
лицензий. Используется для резервной сверки и спорных случаев. Основной источник
сопоставления юрлица в прототипе остаётся DaData.

Страница: https://isga.obrnadzor.gov.ru/accredreestr/opendata/
Постоянная ZIP-выгрузка, опубликованная клиентом официального сайта:
https://isga.obrnadzor.gov.ru/api/spa/accredreestr/opendata/filezip

В отличие от ссылки data-20261018-structure-20160713.xml, ZIP-адрес не содержит
фиксированную дату. Дата снимка извлекается из имени XML внутри ZIP.

Установка и команды

В активированном окружении Python из папки prototype:
  python -m pip install -r requirements.txt
  python -m ou_processor.registry update
  python -m ou_processor.registry status
  python -m ou_processor.registry lookup --inn 7719025840
  python -m ou_processor.registry lookup --name "школа 444" --limit 10

Другая папка хранения:
  python -m ou_processor.registry --cache "/путь/registry_cache" update

По умолчанию registry_cache создаётся рядом с папкой проекта. ZIP и SQLite
не включены в репозиторий: их можно скачать командой update. Для ежедневного
обновления используйте Python виртуального окружения проекта.

Как обновляется резервная копия

1. Проверяются HTTP Last-Modified/ETag, размер и имя файла. Если версия прежняя,
   выполняется только проверка заголовков, архив повторно не скачивается.
2. Новый ZIP скачивается потоково во временный каталог. Проверяются размер,
   SHA-256, целостность читаемого ZIP и XML. Допустим один XML с корнем OpenData.
   Внешние сущности и DTD запрещены. Лимиты: ZIP 2 ГиБ, XML 4 ГиБ, скачивание
   30 минут; сетевой таймаут 60 секунд.
3. XML обрабатывается по одному Certificate, без загрузки гигабайта в память.
   Полный XML отдельно на диск не распаковывается. Создаётся SQLite-индекс.
4. Только после завершения разбора и проверки SQLite переключается current.json.
   При сетевой ошибке, HTML вместо ZIP, повреждении/обрыве XML предыдущая копия
   остаётся рабочей. Ошибка записывается в last_check.json; код завершения 1.
5. Сохраняются два последних успешно опубликованных снимка. --keep позволяет
   увеличить число, минимум 2. --force заставляет скачать и проверить содержимое
   даже при прежних HTTP-заголовках. Одинаковый SHA-256 не создаёт копию снимка.
6. update.lock предотвращает параллельные запуски. После принудительного
   завершения процесса сначала проверьте записанный в файле PID; только после
   подтверждения отсутствия процесса можно удалить оставшийся update.lock.

Состав снимка

  current.json                 Указатель на последнюю рабочую версию
  last_check.json              Последняя проверка, успех или ошибка
  snapshot-ДАТА-ХЕШ/
    source.zip                 Оригинальная официальная выгрузка
    manifest.json              Источник, дата, размер, SHA-256, число записей
    index.sqlite               Индекс организаций и свидетельств

Первый проверенный снимок от 18.10.2026

  ZIP:                         351 894 254 байта
  XML внутри ZIP:            1 022 079 493 байта
  Свидетельств:                        107 438
  Строк организаций/приложений:        504 434

504 434 — не число уникальных школ. В индексе отдельно хранятся свидетельства,
актуальные организации и приложения, включая исторические записи. Одна школа
может встречаться много раз. Размер первого SQLite около 640 МиБ; один снимок
вместе с ZIP занимает примерно 1 ГиБ. Две версии — примерно 2 ГиБ, плюс место
на новую версию во время обновления.

Ограничения и смысл данных

- certificate_status и record_status — статусы аккредитации, не статус юрлица
  в ЕГРЮЛ. Недействующее свидетельство не доказывает ликвидацию школы.
- post_address — исходный PostAddress/EduOrgAddress. Не переименовывается
  в юридический адрес и не переносится автоматически в письмо.
- ИНН филиала не заменяется ИНН головного учреждения. Родительский ИНН хранится
  отдельно в parent_inn. Поля actual_organization не подменяют исторические поля.
- Поиск по ИНН точный. Поиск по названию — вхождение нормализованных слов,
  без нечеткого ранжирования и автоматического подтверждения. Проверяйте номер,
  регион, филиал, дату и статус конкретного свидетельства. По умолчанию выдаётся
  до 20 записей, максимум 100. truncated показывает наличие дополнительных строк.
- Не найдено в реестре аккредитации не означает отсутствие образовательной
  организации или лицензии.
- Реестр доступен отдельной командой lookup для резервной сверки. В полном
  режиме ou_processor.full_run он автоматически используется после DaData,
  если допустимое совпадение не найдено. Неоднозначные ИНН остаются на проверке.
- В локальный поисковый индекс не включаются ФИО учащихся и руководителей,
  телефоны и электронные адреса. ФИО поступивших не участвуют в запросах реестра.

Ежедневный запуск

Для ежедневного обновления настройте в локальном планировщике запуск команды
python -m ou_processor.registry update из папки проекта, используя Python
виртуального окружения. Например, можно выбрать 09:00 по Москве. Расписание
настраивается отдельно на каждом компьютере и не входит в репозиторий.
Основной Excel при обновлении реестра не перезаписывается.

Компьютер должен быть включён, папки проекта и окружения — доступны.
Скачивание требует доступа к isga.obrnadzor.gov.ru. При использовании
автоматизации Codex приложение также должно быть запущено.

Проверено

- Первый полный архив скачан, разобран и опубликован.
- Повторное обновление вернуло unchanged без повторного скачивания.
- Поиск по ИНН Измайловской школы №1508 и по названию школы №444 работает.
- Автономные проверки покрывают повреждения архива/XML, запрет DTD,
  неполное скачивание, сохранение рабочей версии, блокировку конкурирующего
  запуска, хранение двух версий и отсутствие переноса ИНН на филиал.
