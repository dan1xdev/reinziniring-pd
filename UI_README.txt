ИНТЕРФЕЙС И КОМАНДНАЯ СТРОКА

Проверено на Python 3.12. После установки зависимостей:
  python -m ou_processor.web
На macOS можно открыть «Запустить UI.command».
Откроется http://127.0.0.1:8765. Терминал должен оставаться открытым.
Остановка — Ctrl+C. Для другого порта: --port 8766.

1. Выберите или перетащите до 10 файлов .xlsx общим размером до 100 МБ.
2. Для каждой книги выберите рабочий лист или автоматическое определение.
3. Нажмите «Обработать таблицы». API-ключ не нужен.
4. Дождитесь завершения и скачайте Excel и журнал обработки.

Прогресс показывает выполненные шаги. При ошибке выбора листа или формата
выводится понятное сообщение. Одновременно выполняется одна задача.
Можно отменить обработку: файлы и частичный результат запуска удаляются.
Текущий запрос отдельной сверки DaData может завершиться по таймауту
перед отменой.

Обычная обработка использует локальный реестр лицензий и резервный реестр аккредитации.
При отсутствии/повреждении снимка или отсутствии кандидатов случаи
попадают на лист «Проверить». Автоматического обращения к DaData нет,
даже при сохранённом ключе и старом кэше.

ОТДЕЛЬНАЯ СВЕРКА DADATA

Нажмите «Проверить в DaData». Только для этой кнопки нужен ключ в настройках.
Можно сохранить его в системном хранилище, использовать до остановки
сервера или удалить кнопкой. Если сохранить ключ не удалось, снимите флажок
сохранения и повторите запуск. Альтернатива — --ask-token при запуске UI
или переменная DADATA_API_KEY. Это только настройка ключа: обычная обработка
всё равно не обращается к DaData.

Сверка не меняет выбранный реестром ИНН и не подтверждает ненайденные
реестром организации автоматически. Результаты — на «Сверка DaData»,
кандидаты и причины — на «Кандидаты сверки DaData», ошибки — на «Запросы DaData».
Успешные ответы используются из кэша. ФИО и номера дел в API не передаются.

РЕЕСТР И ХРАНЕНИЕ

UI проверяет обновление реестра в фоне и сохраняет предыдущий снимок при сбое.
Статус, попытки и кнопка повтора доступны на странице.
Обновить отдельно:
  python -m ou_processor.registry update
  python -m ou_processor.license_registry update
Регулярное обновление вне UI настраивается отдельно в системном планировщике.
Подробнее: REGISTRY_README.txt.

Результаты: ../ui_runs/<код запуска>/result/schools.xlsx
Заполненные копии входных книг: ../ui_runs/<код запуска>/result/filled_sources/
Ссылки на копии доступны после обработки рядом со ссылкой на итоговый Excel.
Книги с формулами не копируются; ошибка видна в сводке и интерфейсе.
Полный локальный результат: там же result.json
Журнал причин, источников и статусов: там же processing_log.json
Кэш отдельных сверок DaData: ../ui_cache/dadata.json
Реестр: ../registry_cache/
Реестр лицензий: ../license_registry_cache/

После перезапуска старые ссылки UI недоступны, файлы остаются на диске.
Очистка старых запусков выполняется пользователем.
Сервер слушает только 127.0.0.1 и рассчитан на одного пользователя.

Параметры UI:
  --port 8766         Другой локальный порт
  --registry ПАПКА   Снимки реестра
  --licenses ПАПКА   Снимки основного реестра лицензий
  --storage ПАПКА    Входные файлы и результаты
  --cache ФАЙЛ       Кэш отдельной сверки DaData
  --no-browser       Не открывать браузер автоматически

КОМАНДНАЯ СТРОКА

  python -m ou_processor input.xlsx --list-sheets
  python -m ou_processor input.xlsx --sheet "Рабочий лист" --output run_all
  python -m ou_processor input.xlsx --output run_check --check-dadata --ask-token

Можно использовать python -m ou_processor.full_run с теми же параметрами.
Можно передать несколько файлов. --sheet задаёт имя листа для всех книг.
Для разных листов разных книг используйте UI. --output — новая/пустая папка.
--config задаёт правила, --licenses и --registry — снимки. --cache нужен только сверке.
--online — старое имя параметра --check-dadata.
Обычный запуск не запрашивает ключ и не читает кэш DaData.

Коды завершения: 0 — результат готов (ручная очередь возможна),
1 — ошибка обработки, 2 — неполная отдельная сверка DaData или ошибка заполнения копий.

РУЧНЫЕ РЕШЕНИЯ

После обработки в разделе «Ручные решения» скачайте шаблон.
Заполните только «ИНН (выбор оператора)» и «Комментарий». Остальные колонки
не меняйте. Доступны до трёх кандидатов с адресом, баллом и источником.
Пустые ИНН оставляют случаи на проверке. Выбирать можно действующего кандидата
из списка, включая результат явно запущенной сверки DaData.

Загрузите заполненный шаблон .xlsx в тот же раздел. Максимум — 6 МБ и
5 000 строк. При ошибке ИНН, чужом запуске, повторной группе, формулах или
изменении исходных полей решения не применяются. После успешного импорта
статус — ПРОВЕРЕНО. Скачайте обновлённые отчёт, журнал и копии книг.

CLI, без повторного поиска и без DaData:
  python -m ou_processor --result run_all/result.json --import-decisions run_all/manual_decisions.xlsx --output run_checked

Папка run_checked должна быть новой или пустой. Предыдущий результат
сохраняется. Исходные книги должны оставаться доступны по сохранённым путям.
При ошибке заполнения копий отчёт всё равно создаётся, но CLI возвращает 2.

Справочник: ../manual_decisions.json. --decisions-store ПУТЬ задаёт один общий
файл для UI и CLI. Подтверждённые сопоставления применяются до поиска при
следующих запусках. Новые поступившие остаются связанными со своими делами.
Изменение географии, года, вида образования и рисков требует нового решения.
Повреждённый справочник не перезаписывается автоматически.
При нехватке географии, конфликте, обрезанном названии или старом выпуске
требуется ручное подтверждение каждого запуска.
