# reinziniring-pd

Локальное Python-приложение для обработки Excel с образовательными учреждениями: отбор записей, поиск в локальном реестре Рособрнадзора и объединение по ИНН.

Обработка по ТЗ использует реестр лицензий и автоматически подключает DaData при настроенном ключе. Без ключа результат формируется по локальным источникам с явным предупреждением об ограничении проверки.

## Установка и интерфейс

Проверено на Python 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ou_processor.web
```

На Windows активация: `.venv\Scripts\activate`. Откройте http://127.0.0.1:8765. На macOS после установки можно открыть «Запустить UI.command». Терминал должен оставаться открытым.

1. Загрузите файлы .xlsx.
2. Для каждой книги выберите рабочий лист или автоматическое определение.
3. При наличии ключа укажите его в настройках DaData и нажмите «Обработать по ТЗ». Без ключа доступен локальный прогон.
4. Скачайте Excel, журнал обработки и заполненные копии исходных книг.

Доступны прогресс, отмена, повтор получения статуса. Отмена удаляет файлы и частичный результат текущего запуска. Лимиты: 10 файлов, 100 МБ суммарно, 5 000 строк за запуск.

## Источник данных

По умолчанию используется **реестр лицензий**. DaData уточняет адрес и юридический статус по найденному ИНН; если реестр не дал надёжного результата, предлагает кандидатов оператору. Конфликт ИНН отменяет автоматический выбор. Реестр аккредитации доступен только при явной настройке `allow_accreditation_fallback: true`.

UI проверяет обновления в фоне и сохраняет предыдущий снимок при ошибке. Если реестр недоступен, повреждён или совпадений нет, обработка продолжается через DaData с настроенным ключом. Кандидаты без подтверждения реестром и спорные случаи сохраняются для ручной проверки.

```bash
python -m ou_processor.registry update
python -m ou_processor.license_registry update
```

Реестр занимает примерно 1 ГБ на снимок; сохраняются минимум два снимка. Подробнее: [REGISTRY_README.txt](REGISTRY_README.txt).

## Входные таблицы

Обязательны «ФИО» и «Образовательное учреждение» (или «Название ОУ в исходном Excel»). Вид образования или тип документа используются для отбора; номер личного дела, регион и город дополняют запись. Варианты заголовков задаются в `input_column_aliases` файла `config.json`.

Автоматический режим читает первый содержательный лист, пропуская служебные списки «ВУЗы», «Не нашли», «Коллективу …» и копии. Явный выбор обрабатывает только выбранный лист. Неизвестный лист вызывает ошибку со списком доступных. Ведущие нули сохраняются, отсутствующие данные не восстанавливаются по предположению.

## Командная строка

Оба входа запускают общий полный сценарий: `python -m ou_processor` и `python -m ou_processor.full_run`.

```bash
python -m ou_processor input.xlsx --list-sheets
python -m ou_processor input.xlsx --sheet "Рабочий лист" --output run_all
python -m ou_processor.full_run input.xlsx --output run_all --licenses ../license_registry_cache --registry ../registry_cache
```

Можно передать несколько файлов. В CLI `--sheet` задаёт одинаковое имя листа для всех книг, в UI лист выбирается отдельно для каждой книги. `--output` — новая/пустая папка. `--config` — файл правил. Исходные книги не изменяются. Прежний демонстрационный CLI заменён общим полным сценарием.

## Подключение DaData

```bash
python -m ou_processor input.xlsx --output run_all --ask-token
```

CLI автоматически читает `DADATA_API_KEY`; `--ask-token` запрашивает ключ без отображения ввода. В UI используются введённый ключ, ключ сервера или сохранённый системным хранилищем ключ. Основная кнопка «Обработать по ТЗ» запускает весь доступный каскад. Кнопка «Обработать с DaData» и совместимые CLI-флаги `--check-dadata` / `--online` дополнительно требуют наличие ключа.

ФИО и номера дел остаются локально; DaData получает только сведения об организациях. Ключ не включается в API-ответы и журналы. Без подтверждения действующего юридического лица запись остаётся на проверке. Без ключа обработка не падает, но предупреждает, что адрес и юридический статус не уточнены через DaData.

Коды завершения CLI: 0 — результат сформирован, 1 — ошибка обработки, 2 — ошибка или пропуск запроса DaData. Случаи для ручной проверки отражены в результате даже при коде 0.

## Результаты и хранение

`schools.xlsx` содержит «Учреждения», «Ученики и дела», «Письма», «Ручная проверка», «Проверить», «Сводка», «Исходные записи», «Кандидаты» и «Источники». «Запросы DaData» содержит журнал обращений автоматического каскада; при использовании DaData также сохраняются итоги сверки и кандидаты.

В `filled_sources/` создаются отдельные копии входных книг с заполненными названием в именительном и родительном падеже, адресом и индексом. Исходники не меняются; спорные значения не записываются. В копиях сохраняются формулы и их кэшированные результаты, служебные листы и нетронутые части XLSX. Ошибки заполнения копий видны в сводке и интерфейсе.

`result.json` — полный локальный результат. `processing_log.json` — режим, даты, снимок реестра, исходные листы, причины отбора, статусы, ИНН, источники, оценки кандидатов и причины отказа. ФИО и номера личных дел в отдельный журнал не включаются.

Файлы UI: `../ui_runs/<код запуска>/result/`. Кэш ответов DaData: `../ui_cache/dadata.json`. Реестры: `../license_registry_cache/` и `../registry_cache/`. Пути меняются через `--storage`, `--cache`, `--licenses`, `--registry`. Старые запуски удаляются пользователем. После перезапуска UI прежние ссылки недоступны, файлы остаются на диске. Сервер слушает только 127.0.0.1.
