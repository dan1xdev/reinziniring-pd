# reinziniring-pd

Локальное Python-приложение для обработки Excel с образовательными учреждениями:
отбор записей, поиск организаций через DaData и резервный реестр аккредитации
Рособрнадзора, объединение разных написаний по ИНН.

Результат — Excel: **одно учреждение → адрес → ФИО учеников → номера личных дел**.
Неоднозначные совпадения сохраняются отдельно для проверки.

## Быстрый запуск

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/dan1xdev/reinziniring-pd.git
cd reinziniring-pd
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ou_processor.web
```

На Windows вместо `source` выполните `.venv\Scripts\activate`.

Откройте **http://127.0.0.1:8765**. Загрузите один или несколько файлов `.xlsx`,
введите свой API-ключ DaData в настройках и нажмите «Обработать таблицы».
После завершения доступны предпросмотр, ручная проверка спорных совпадений и скачивание Excel. По умолчанию новые запросы в DaData отключены.

На macOS после установки можно запускать приложение через `Запустить UI.command`.
Терминал должен оставаться открытым; остановка — `Ctrl+C`.

## Ручная проверка и решения

В обычном режиме приложение не отправляет запросы в DaData: используются сохранённые ответы и локальный реестр. Для отдельной проверки нажмите «Проверить в DaData» у спорной записи и введите ключ. Передаётся название учреждения и география; ФИО и номера личных дел в этот запрос не входят.

Для ручного сопоставления выберите одного из показанных кандидатов и подтвердите ИНН. Решения хранятся локально в `manual_decisions.json` рядом с папкой запусков и повторно применяются при следующих обработках. Статус такого сопоставления — `ПРОВЕРЕНО`. Конфликтующие варианты ИНН не выбираются автоматически. Комментарий сохраняется вместе с решением.

## Ключ DaData

**API-ключей в репозитории нет.** Ключ из интерфейса при отмеченном флажке
сохраняется в системном хранилище ключей компьютера и загружается при следующем
запуске. Его можно удалить в настройках. Для ввода ключа только в память сервера:

```bash
python -m ou_processor.web --ask-token
```

Также поддерживается переменная окружения `DADATA_API_KEY`. Файлы `.env`
автоматически не читаются. Не помещайте реальные ключи в исходники или коммиты.

ФИО и номера личных дел обрабатываются локально. В DaData отправляются только
названия и география организаций. Сервер слушает только `127.0.0.1`.

## Входные таблицы

Обязательны колонки:

- `Образовательное учреждение` (или `Название ОУ в исходном Excel`);
- `Вид образования` или `Тип документа об образовании`.

Для результата с учениками нужны `ФИО` и `Личное дело.Номер` либо
`Номер личного дела`. Регион и город повышают точность поиска.
Все поддерживаемые названия колонок перечислены в `ou_processor/input.py`.

Интерфейс принимает до 10 файлов, до 100 МБ суммарно и до 5 000 строк за запуск.
Отсутствующие ФИО, номера дел и неоднозначные адреса не заполняются предположениями.

## Результат и ограничения

- `Учреждения`: одна строка на сопоставленный ИНН.
- `Ученики и дела`: связанные пары ФИО и номера дела без повторов внутри ИНН.
- `Проверить`: спорные случаи и кандидаты.
- `Сводка`, `Исходные записи`, `Запросы DaData`, `Кандидаты`, `Источники`: аудит обработки.

Адрес DaData — юридический адрес. Адрес реестра аккредитации требует сверки
актуальности и может отличаться от адреса учебного корпуса. Правила сопоставления
эвристические: это прототип, не гарантия точности и не автоматическая проверка
правопреемства. Филиалы, обрезанные названия и недостаточная география могут
потребовать ручного решения.

Исходные таблицы, пользовательские результаты, ключи и большие реестры в репозиторий
не включены. В тестах используются синтетические данные.

## Локальное хранение и реестр

По умолчанию рядом с папкой проекта создаются:

- `ui_runs/`: загруженные файлы и результаты отдельных запусков;
- `ui_cache/`: ответы DaData об организациях;
- `registry_cache/`: скачанные снимки реестра и локальный индекс.

UI проверяет и обновляет реестр в фоне при запуске. При временной сетевой ошибке
выполняются три попытки; загрузку можно повторить кнопкой без перезапуска.
Предыдущий снимок используется во время обновления. Если его нет, обработка
через DaData доступна, а ненайденные учреждения остаются на листе «Проверить».
Отдельно обновить резервный реестр:

```bash
python -m ou_processor.registry update
```

Скачивание и индексация требуют времени и примерно 1 ГБ дискового пространства
на снимок; по умолчанию сохраняются два снимка. Это реестр **аккредитации**, а не
реестр лицензий. Ежедневный запуск команды нужно настроить отдельно в планировщике.

Пути можно изменить через `--storage`, `--cache` и `--registry` у веб-интерфейса.
Загрузки и результаты остаются на диске после завершения работы; старые запуски
удаляются пользователем вручную. После перезапуска сервера прежние ссылки
скачивания недоступны, но файлы остаются в `ui_runs/`.

## Командная строка

```bash
python -m ou_processor.full_run input.xlsx --output run_all --cache dadata_cache.json --online --ask-token
```

Без `--online` и `--ask-token` используются сохранённые ответы и локальный реестр.
Ошибки или пропуски API отмечаются в результате и дают код завершения `2`.

## Проверки

```bash
python -m unittest discover -s tests -q
```

Тесты проверяют обработку данных, идентификацию, реестр, загрузку файлов
и локальные HTTP-маршруты. Для HTTP-тестов нужен доступ к loopback-интерфейсу;
внешняя сеть не используется. `verify_demo.py` и `verify_full.py` предназначены
для исходной контрольной выборки, которая не входит в репозиторий.

Подробности: [интерфейс](UI_README.txt), [правила обработки](README.txt),
[резервный реестр](REGISTRY_README.txt).

## Вторая итерация — ручная проверка (задача Павленко Ивана)

После обработки откройте раздел «Ручная проверка». Для спорной группы показаны до трёх кандидатов (название, ИНН, адрес, балл и источник), а также причина отказа от автоматического выбора. Подтвердите ИНН и при необходимости оставьте комментарий. Программа проверяет контрольные цифры ИНН и требует, чтобы выбранный ИНН был среди кандидатов группы.

Для массовой работы нажмите «Скачать файл для ручных решений». В книге на листе «Решения» заполните колонку «ИНН (выбор оператора)» и при необходимости «Комментарий». Не меняйте идентификаторы групп и исходные поля. Затем выберите файл в поле «Загрузить заполненный файл решений». Импорт проверяет заголовки, исходные поля, дубликаты групп, ИНН, принадлежность ИНН кандидатам и длину комментария. При ошибках весь импорт отклоняется, список ошибок показывается пользователю.

Подтверждения сохраняются в `manual_decisions.json` рядом с `ui_runs`. В итоговом Excel организация получает статус `ПРОВЕРЕНО`, исходные записи сохраняют ИНН, статус и комментарий. При следующих запусках сохранённые сопоставления применяются до поиска, без повторных запросов по этим группам. Ключ сопоставления включает нормализованные название, регион и город. При изменении этих данных автоматическое повторное применение не происходит.

Кнопка «Проверить в DaData» запускает отдельный запрос с вводом ключа, отображает найденные варианты и предупреждает о расхождении ИНН. Конфликтующий ИНН не принимается автоматически. Факты ручных запросов отражаются на листе «Ручные проверки DaData». Обычная обработка без включения онлайн-режима не вызывает DaData.

Ограничение: автоматическое определение достоверности документов и правопреемства не выполняется; оператор должен проверять кандидата по надёжному источнику. Сохранённый ИНН повторно применяется к идентичному нормализованному названию и географии, поэтому неоднозначные одноимённые организации требуют отдельного контроля.
