# reinziniring-pd

Локальное Python-приложение для обработки Excel с образовательными учреждениями: отбор записей, поиск в локальном реестре Рособрнадзора и объединение по ИНН.

Обычная обработка работает без ключа и обращений к DaData. Отдельная сверка показывает совпадения и конфликты, сохраняя результат реестра.

## Установка и интерфейс

Проверено на Python 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ou_processor.web
```

На Windows активация: `.venv\Scripts\activate`. Откройте http://127.0.0.1:8765. На macOS после установки можно открыть «Запустить UI.command». Терминал должен оставаться открытым.

1. Загрузите файлы .xlsx.
2. Для каждой книги выберите рабочий лист или автоматическое определение.
3. Нажмите «Обработать таблицы». Ключ не нужен.
4. Скачайте Excel и журнал обработки.

Доступны прогресс, отмена, повтор получения статуса. Отмена удаляет файлы и частичный результат текущего запуска. Лимиты: 10 файлов, 100 МБ суммарно, 5 000 строк за запуск.

## Источник данных

По умолчанию используется **реестр лицензий**. Реестр аккредитации служит резервным источником.

UI проверяет обновления в фоне и сохраняет предыдущий снимок при ошибке. Если реестр недоступен, повреждён или совпадений нет, случаи передаются на лист «Проверить» с предупреждением. Автоматического перехода к DaData нет; старый кэш DaData в обычном режиме не читается.

```bash
python -m ou_processor.registry update
python -m ou_processor.license_registry update
```

Реестр занимает примерно 1 ГБ на снимок; сохраняются минимум два снимка. Подробнее: [REGISTRY_README.txt](REGISTRY_README.txt).

## Входные таблицы

Обязательны «Образовательное учреждение» (или «Название ОУ в исходном Excel») и «Вид образования» либо «Тип документа об образовании». Для списка поступивших нужны «ФИО» и «Личное дело.Номер» либо «Номер личного дела». Регион и город помогают поиску. Поддерживаемые заголовки: `ou_processor/input.py`.

Автоматический режим сохраняет прежние правила: при наличии листа «100 записей» читает только его, пропускает служебные списки «ВУЗы», «Не нашли» и копии. Явный выбор обрабатывает только выбранный лист. Неизвестный лист вызывает ошибку со списком доступных. Ведущие нули сохраняются, отсутствующие данные не восстанавливаются по предположению.

## Командная строка

Оба входа запускают общий полный сценарий: `python -m ou_processor` и `python -m ou_processor.full_run`.

```bash
python -m ou_processor input.xlsx --list-sheets
python -m ou_processor input.xlsx --sheet "Рабочий лист" --output run_all
python -m ou_processor.full_run input.xlsx --output run_all --licenses ../license_registry_cache --registry ../registry_cache
```

Можно передать несколько файлов. В CLI `--sheet` задаёт одинаковое имя листа для всех книг, в UI лист выбирается отдельно для каждой книги. `--output` — новая/пустая папка. `--config` — файл правил. Исходные книги не изменяются. Прежний демонстрационный CLI заменён общим полным сценарием.

## Отдельная сверка DaData

```bash
python -m ou_processor input.xlsx --output run_check --check-dadata --ask-token
```

В UI используйте кнопку «Проверить в DaData». Ключ нужен только для неё. Можно сохранить его в системном хранилище или удалить в настройках. Для CLI альтернатива вводу — переменная `DADATA_API_KEY`, читаемая только при `--check-dadata`. Старое имя `--online` оставлено как псевдоним отдельной сверки.

Сверка не заменяет выбранный реестром ИНН и не подтверждает ненайденные реестром организации автоматически. ФИО и номера дел остаются локально; DaData получает только сведения об организациях. Ключ не включается в API-ответы и журналы.

Коды завершения CLI: 0 — результат сформирован, 1 — ошибка обработки, 2 — неполная отдельная сверка DaData. Случаи для ручной проверки отражены в результате даже при коде 0.

## Результаты и хранение

`schools.xlsx` содержит «Учреждения», «Ученики и дела», «Проверить», «Сводка», «Исходные записи», «Кандидаты», «Источники» и листы подготовки писем. «Запросы DaData» пуст в обычном режиме; при отдельной сверке дополнительно создаются «Сверка DaData» и «Кандидаты сверки DaData».

`result.json` — полный локальный результат. `processing_log.json` — режим, даты, снимок реестра, исходные листы, причины отбора, статусы, ИНН, источники, оценки кандидатов и причины отказа. ФИО и номера личных дел в отдельный журнал не включаются.

Файлы UI: `../ui_runs/<код запуска>/result/`. Кэш отдельных сверок: `../ui_cache/dadata.json`. Реестры: `../license_registry_cache/` и `../registry_cache/`. Пути меняются через `--storage`, `--cache`, `--licenses`, `--registry`. Старые запуски удаляются пользователем. После перезапуска UI прежние ссылки недоступны, файлы остаются на диске. Сервер слушает только 127.0.0.1.
